# v3.7 — Deferred Human Review Center

## Why

Some Nexus pages are not ordinary “one Main File + optional patch” updates. They contain several mutually exclusive product branches, texture tiers, body variants, HDT/non-HDT variants, split/full archives, hotfixes, or many compatibility patches.

For those pages, preserving the currently installed branch is not always what the user wants, while automatically switching branches is too risky.

v3.7 therefore uses a hybrid policy:

1. high-confidence, ordinary updates continue automatically;
2. multi-variant / ambiguous / complex patch items are skipped during the automatic stage;
3. after the automatic stage finishes, a local Review Center is opened;
4. the user selects the exact Main branch and Patch decisions;
5. only exact candidates already present in the report can be authorized;
6. reviewed downloads still go through preflight, the global executor lock, queue idempotency, MO2 UI Guard, and final VERIFIED checks.

## Example: Sassy Salt and Wind Hair Retexture

A page may expose separate Main files for Vanilla, KS Hairdos Full, KS Hairdos HDT-SMP, split/partial files, and other product branches. If the current installation is Vanilla but the local MO2 environment contains KS Hairdos HDT-SMP, the planner may recommend KS HDT, but it must not migrate branches without user confirmation.

Expected state:

```text
HOLD_VARIANT_REVIEW
```

The Review Center then shows the available exact file IDs, current branch, environment match, and recommendation.

## Run artifacts

Each pipeline run can produce:

```text
.runtime/runs/<timestamp>/
  review-center.json
  review-center.html
  review-center-config.json
  review-decisions.json
  review-server.json
  review-jobs/
```

`review-center.html` is readable as a static report. Static `file://` mode is intentionally read-only.

Interactive mode is served only on loopback:

```powershell
npm run review -- --run ".runtime\runs\<timestamp>"
```

A `--go` pipeline automatically starts and opens the Review Center after the automatic stage when pending review items exist. Use `--no-open-review` to suppress this.

## Main branch decisions

For `HOLD_VARIANT_REVIEW`, Main file options are radio buttons. The report shows:

- exact `fileId`;
- Nexus version;
- semantic branch tags;
- whether it is the currently installed branch;
- local-environment match score;
- AI recommendation (advisory only);
- file description.

The browser cannot submit an arbitrary file ID. `review-download.js` verifies that the selected file is one of the server-generated candidates.

## Patch family decisions

Each unresolved patch family must receive one explicit decision:

- `DOWNLOAD` — download one exact candidate;
- `NOT_APPLICABLE` — not needed for this local mod environment;
- `ALREADY_INCLUDED` — already present/included;
- `OBSOLETE` — old/replaced/no longer needed;
- `SKIP_FOR_NOW` — defer the whole reviewed item.

`DOWNLOAD` is only permitted when the candidate already has an exact `modId + fileId`. A discovered independent patch page without an exact file ID is displayed but cannot be downloaded until Pi/Agent resolves the exact file.

## Coverage safety

If Patch Discovery could not prove a required source was inspected (for example Nexus Requirements/Description parsing failed), a browser click does not override that uncertainty. `review-download.js` blocks the reviewed transaction until coverage is resolved.

This means “human review” authorizes a known option; it is not a bypass around unknown patch coverage.

## Local server security

The Review Center server:

- binds to `127.0.0.1` only;
- uses a random per-process token in the URL;
- rejects non-loopback clients;
- refuses a second reviewed download while one is already running;
- writes decisions to the current run directory;
- never exposes Nexus API key contents to the HTML;
- launches reviewed downloads through `execute-plan.js` rather than direct browser clicking.

## Reviewed transaction ordering

A user-selected branch and patches become a normal transaction:

```text
SELECTED MAIN
  -> VERIFIED
  -> SELECTED PATCH #1
  -> VERIFIED
  -> SELECTED PATCH #2
  -> VERIFIED
```

Existing v3.4/v3.5 protections remain authoritative:

- exact Downloads `.meta/.unfinished` inspection;
- cross-run submission ledger;
- one global executor lock;
- duplicate-NXM suppression;
- safe MO2 duplicate-dialog handling;
- exact file ID verification;
- 7-Zip archive validation.

## Operational rule for Pi Agent

Pi Agent must not decide a branch switch on the user's behalf when the planner returns `HOLD_VARIANT_REVIEW`.

It may:

- enrich evidence;
- resolve candidates missing exact file IDs;
- explain why one branch is likely appropriate;
- populate the report.

The final branch migration choice remains user-controlled through the Review Center unless the user explicitly instructs Pi to choose a named branch.
