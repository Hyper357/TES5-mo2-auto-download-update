# v3.2 Diagnostics / Flight Recorder

v3.2 的目标不是增加更多“AI 猜测”，而是让自动下载链具备可观测性、可诊断性和有限的安全恢复能力。

## 1. 故障域

一次 Nexus -> MO2 下载会经过多个独立故障域：

```text
Planner / Registry
  -> Nexus API
  -> CDP Browser / Login
  -> Nexus DOM / exact file card
  -> short-lived nxm:// extraction
  -> nxmhandler / MO2 instance
  -> MO2 download queue / CDN
  -> archive + .meta landing
  -> 7-Zip + modId/fileId/version verification
```

v3.2 为这些层建立统一错误码。Pi/AI Agent 不应该根据一段自由文本猜原因，而应优先使用 `errorCode + layer + retryable + action`。

## 2. 每轮运行目录

```text
.runtime/runs/<timestamp>/
  logs/
    pipeline.log      # 人类快速阅读
    events.jsonl      # Agent/程序读取的全部结构化事件
    errors.jsonl      # 仅 ERROR 事件
  diagnostics/
    environment.json  # --diagnose / --go preflight
    failed-items.json # 失败项摘要
    *browser*.json    # 浏览器/NXM 事故现场元数据
  screenshots/
    *.png             # Browser/NXM 层失败时的 best-effort 截图
  execution-state.json
  final-report.json
```

日志会脱敏 `key / expires / user_id / token / Authorization / Cookie / API key` 等敏感信息。任何 Agent 也不得手工把完整签名 NXM 写入报告。

## 3. Diagnose 模式

```powershell
node index.js "E:\SkyrimAE\mo2\mods" "E:\SkyrimAE\tools\.nexus_api_key" --diagnose
```

该模式不下载，检查：

- Mods 目录；
- Downloads 目录与写权限；
- Nexus API key 与 `/users/validate`；
- CDP 9222；
- nxmhandler.exe；
- ModOrganizer.exe；
- 7-Zip。

结果：

- `HEALTHY`：环境门禁通过；
- `DEGRADED`：存在非阻断警告；
- `UNHEALTHY`：真实 `--go` 必须被阻止。

## 4. Debug 模式

```powershell
node index.js "E:\SkyrimAE\mo2\mods" "E:\SkyrimAE\tools\.nexus_api_key" --go --debug
```

Debug 会额外写入轮询、attempt 和详细阶段事件，但仍然不保存 Cookie、密码或完整 NXM 签名。

## 5. 安全重试

执行器默认：

```text
maxSubmitAttempts = 2
retryDelaySec = 5
```

可配置：

```powershell
--max-submit-attempts 2 --retry-delay-sec 5
```

只有错误目录明确标记 `retry=true` 才允许自动重试。典型可重试：

- API 429 / timeout；
- CDP 临时连接失败；
- NXM 提取失败/签名过期；
- nxmhandler 临时失败；
- MO2 队列暂时不可见；
- verify timeout。

选择/身份/完整性错误必须熔断，例如：

- FILEID_MISMATCH；
- META_MISMATCH；
- VERSION_MISMATCH；
- VARIANT_CONFLICT；
- DOM_FILE_NOT_FOUND；
- DOM_SELECTOR_CHANGED；
- CLOSURE_CONFLICT。

这是为了防止“不断重试，最终点到了别的文件”。

## 6. Browser/NXM 事故现场

当错误属于 Browser/NXM 层，执行器会 best-effort 连接 `127.0.0.1:9222`：

- 找到当前 Nexus 页面；
- 保存当前 URL 的脱敏版本；
- 保存 page title；
- 检查 sign-in / Cloudflare 文本特征；
- 收集 DOM 中可见的 `data-file-id`；
- 保存有限 body text sample；
- 保存当前视口截图。

不保存 Cookie，不导出浏览器 profile，不保存完整页面 HTML。

## 7. Pi Agent 故障处理顺序

固定使用以下顺序：

```text
errors.jsonl
  -> failed-items.json
  -> execution-state.json
  -> browser diagnostic JSON / screenshot (if present)
  -> source code only if evidence points to a code defect
```

若错误是 retryable，恢复当前 `modId:fileId`；若不是 retryable，先解决根因再重新规划。不得默认整批重跑。

## 8. 成功语义

Flight Recorder 不改变成功定义：

```text
SUBMITTED != success
LANDED != success
VERIFIED == success
```

同一 transaction 中，MAIN 未 VERIFIED 时，PATCH / TRANSLATION 必须保持阻断。
