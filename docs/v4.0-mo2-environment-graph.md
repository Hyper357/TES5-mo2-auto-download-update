# v4.0 — MO2 Environment Graph

## Goal

Move applicability decisions from fuzzy “installed folder names” toward the **active MO2 Profile**.

v4.0 does not try to automate MO2 installation or plugin sorting. It creates a deterministic environment fact surface used by Main/variant selection and Component Discovery.

## Sources of truth

The graph reads:

```text
<profile>/modlist.txt
<profile>/plugins.txt
<profile>/loadorder.txt
mods/*/meta.ini
mods/*/*.esp|esm|esl
```

It deliberately does **not** use MO2 red warning/exclamation icons as authoritative evidence.

A Nexus author can enter unusual version metadata and MO2 can display a warning even when the exact installed Nexus file is valid. Therefore:

```text
uiWarningPolicy.trustedForUpdateDecision = false
```

Exact local/Nexus identity remains authoritative.

## Profile resolution

Order:

1. explicit `MO2_PROFILE_DIR` / `--profile-dir`;
2. explicit `MO2_PROFILE_NAME` / `--profile-name`;
3. selected profile from portable `ModOrganizer.ini`;
4. unique sole profile only.

If multiple profiles exist and no current profile can be proven:

```text
PROFILE_UNRESOLVED
```

The pipeline may still audit installed Nexus files, but negative environment inference is disabled.

## Graph model

Each mod entry records:

```text
name
state = ENABLED | DISABLED | UNLISTED | SEPARATOR
profileOrder
modId
version
installationFile
installedFiles[]
plugins[]
```

Plugin nodes record:

```text
name
enabled
loadOrderIndex
owners[]
ownerState
```

The graph also reports missing modlist entries and unlisted folders instead of silently assuming either state.

## Active context rule

When Profile resolution is reliable:

- all installed Nexus mods remain eligible for update scanning;
- only **ENABLED** mods feed runtime/body/variant/compatibility context;
- disabled mods do not make the current environment look like they are active.

This is especially important for compatibility ecosystems such as Lux, USSEP, JK, HDT-SMP, body frameworks and runtime branches.

## Component applicability

Environment Graph evidence is attached to each Component candidate.

The only automatic negative resolution introduced in v4.0 is deliberately narrow:

```text
candidate.kind in PATCH | HOTFIX
AND candidate.family is a recognized compatibility family
AND active Profile is resolved
AND counterpart state is definitively DISABLED_ONLY or ABSENT
=> NOT_APPLICABLE, confidence=high, source=ENVIRONMENT_GRAPH
```

This conclusion is recalculated from the current Profile every run; it is not written as permanent registry truth.

### Why required components are different

Forward Requirements are dependency evidence. If the required dependency is disabled or absent:

```text
REQUIRED_DEPENDENCY_DISABLED
REQUIRED_DEPENDENCY_ABSENT
```

The candidate remains unresolved/HOLD. Absence of a requirement is not evidence that the requirement is unnecessary.

Likewise, v4.0 does not auto-dismiss PHYSICS, BODYSLIDE, TEXTURE, MESH, CONFIG or OPTIONAL_COMPONENT merely because a counterpart is not found.

## Closure integration

Component Discovery may mark a PATCH/HOTFIX candidate as environment-resolved `NOT_APPLICABLE`. Closure Gate accepts that decision only when:

```text
source == ENVIRONMENT_GRAPH
resolved == true
confidence == high
status == NOT_APPLICABLE
```

Every other candidate still needs normal registry/user resolution. Translation remains an explicit baseline closure decision.

## Review Center

Review data now includes:

- active Profile name/source;
- each reviewed mod's Profile state;
- Environment reason/evidence on unresolved candidates;
- dependency-disabled / dependency-absent badges.

This makes the remaining human decisions easier without turning environment hints into user authorization.

## CLI

```powershell
npm run environment:status
```

Optional explicit profile selection:

```powershell
$env:MO2_PROFILE_NAME = "Default"
npm run environment:status
```

or:

```powershell
$env:MO2_PROFILE_DIR = "E:\SkyrimAE\mo2\profiles\Default"
npm run environment:status
```

Each pipeline run writes:

```text
.runtime/runs/<timestamp>/mo2-environment.json
```

`npm run agent:status` exposes a compact environment summary instead of requiring agents to read the full graph.

## Safety invariants

v4.0 does not weaken:

- exact Main/fileId selection;
- Variant Decision Memory drift protection;
- Component Discovery coverage;
- REQUIRED exact aux identity + API audit;
- Browser isolation;
- executor lock and submission ledger;
- MO2 duplicate-submit UI Guard;
- VERIFIED completion semantics.

Most importantly:

> A MO2 red exclamation mark is not an update command.
