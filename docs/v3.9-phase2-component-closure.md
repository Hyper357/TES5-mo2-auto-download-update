# v3.9 Phase 2 — Generalized Component Closure

## Goal

Prevent a correct Main File update from silently omitting required non-Patch companion files.

The old closure model was primarily:

```text
MAIN -> PATCH(es) -> TRANSLATION
```

Phase 2 generalizes discovery and closure to:

```text
MAIN
  -> RESOURCE
  -> MESH
  -> TEXTURE
  -> PHYSICS
  -> BODYSLIDE
  -> CONFIG
  -> HOTFIX
  -> PATCH
  -> TRANSLATION
  -> OPTIONAL_COMPONENT
```

The list is a discovery taxonomy, not an instruction to download everything.

## Safety rule

**Discovered != Required.**

Every discovered component family must be explained as one of:

```text
REQUIRED
NOT_APPLICABLE
ALREADY_INCLUDED
OBSOLETE
```

Only `REQUIRED` creates a download row, and it must contain exact:

```text
auxModId
auxFileId
auxVersion
auxName
```

and pass `audit-registry.js`.

## Discovery sources

Phase 2 uses:

1. same-page Nexus Files explicitly recognizable as components;
2. forward Nexus Requirements — dependencies/resources required by the Main;
3. reverse `Mods requiring this file` — useful for independent patches/translations/add-ons;
4. Description links and explicit component/requirement text;
5. installed MO2 context;
6. local FOMOD option names;
7. the existing learned independent Patch relation registry.

Forward Requirements are particularly important because they can reveal framework/library/resource dependencies that a Patch-only workflow misses.

## Component classification

The classifier is intentionally explicit. Generic Update/Misc files are not automatically treated as components unless their file name/description contains component evidence.

Examples:

```text
Required Framework                       -> RESOURCE
KS Hairdos HDT-SMP Physics Files         -> PHYSICS
CBBE 3BA BodySlide                       -> BODYSLIDE
2K texture pack                          -> TEXTURE
Mesh replacer                            -> MESH
INI preset / config                      -> CONFIG
HOTFIX - missing textures                -> HOTFIX
USSEP compatibility patch                -> PATCH
Chinese Translation                      -> TRANSLATION
Optional add-on                          -> OPTIONAL_COMPONENT
```

## Closure behavior

If any source coverage cannot be proven, or any candidate family is unresolved:

```text
HOLD_COMPONENT_DISCOVERY
```

If registry decisions are stale, invalid, conflicting, or missing where required:

```text
HOLD_COMPONENT_CLOSURE
HOLD_CLOSURE_CONFLICT
```

Main cannot enter the automatic download manifest.

Translation remains an explicit baseline closure decision because an independent translation page cannot always be proven from one Main page scan.

## Review Center

Complex component decisions are grouped by:

```text
kind + family
```

Example:

```text
RESOURCE · CUSTOM:REQUIRED_FRAMEWORK
PHYSICS · CUSTOM:HDT_SMP
HOTFIX · CUSTOM:MISSING_TEXTURES
PATCH · USSEP
BODYSLIDE · CUSTOM:CBBE_3BA
```

For each group the user can choose:

```text
DOWNLOAD exact candidate
NOT_APPLICABLE
ALREADY_INCLUDED
OBSOLETE
SKIP_FOR_NOW
```

A candidate without exact `modId:fileId` cannot be selected for download.

## Held Main restoration

If Main selection was already deterministic but only component discovery blocked it, the Review item retains the exact Main target.

After the user resolves all component groups, reviewed download generates one transaction containing:

```text
exact Main target
+ exact selected REQUIRED components
```

This fixes the old edge case where a human Patch decision could download only the Patch while leaving the held Main out of the reviewed transaction.

## Compatibility

Historical filenames remain for now:

```text
patch-discovery.json
patch-discovery-tasks.tsv
scripts/discover-patches.js
scripts/discover-all-patches.js
```

Their v3.9 Phase 2 contents are generalized component discovery. This avoids breaking existing Pi scripts while the project transitions terminology.

New npm alias:

```powershell
npm run discover-components
```

`npm run discover-patches` remains as a compatibility alias.

## Deliberate non-goals

Phase 2 does not:

- automatically install archives;
- automatically operate the MO2 FOMOD installer;
- automatically choose Optional components;
- treat `requiredHint` as sufficient proof to download;
- remove Patch/Translation compatibility behavior.

FOMOD-aware installation intent is a later phase.
