# v3.1 架构：Evidence-Bound Update Pipeline

v3.1 的目标不是让 AI “更大胆地自动下载”，而是把 AI 限定为**调查与证据补全层**，把最终下载资格交给确定性程序门禁。

## 1. 七段流水线

```text
MO2 本地状态
  ↓
check-outdated.js
  ├─ 锚定 installed fileId / installationFile
  ├─ 主文件候选打分
  ├─ 运行时/身形/分辨率/CC 变体冲突
  └─ Patch / Translation 候选证据
  ↓
plan.json
  ↓
audit-registry.js
  └─ 验证 REQUIRED aux modId/fileId/version 仍真实有效
  ↓
registry-audit.json
  ↓
closure-gate.js
  ├─ PATCH 必须闭合
  ├─ TRANSLATION 必须闭合
  ├─ registry 必须绑定 mainFileId
  ├─ 结论必须新鲜
  └─ scanner evidence 与 NONE 冲突时拒绝放行
  ↓
manifest-final.tsv
  ↓
build-review-queue.js
  └─ 把所有 HOLD 转换成 Pi/AI 可执行核验任务
  ↓
review-queue.tsv / review-queue.json
  ↓
execute-plan.js (--go only)
  ├─ 主文件优先
  ├─ Patch
  ├─ Translation
  ├─ 每项单独提交
  ├─ 每项等待 verify
  └─ execution-state.json 持久化
  ↓
nexus-autodl.js verify
  ↓
VERIFIED only
```

## 2. 主文件选择不变量

自动目标必须同时满足：

1. 本地来源可解析；
2. 候选不是 OLD / ARCHIVED；
3. 文件角色与当前来源兼容；
4. 没有明确 runtime / body / resolution / CC 冲突；
5. 版本不是降级；
6. 候选分数达到阈值；
7. 与第二候选有足够 margin；
8. 不是同版本不同 fileId 的未经核验替换包；
9. 置信度为 high。

否则产生 HOLD，而不是猜。

## 3. Profile 只是弱证据

旧逻辑会在证据不足时默认：

```text
AE + 3BA + 2K
```

v3.1 改为：

```text
UNKNOWN
```

只有本地已安装文件中存在足够明确且有优势的 token 时，才推导 AE/SE/VR、3BA/CBBE/BHUNP/UNP、1K/2K/4K/8K。

UNKNOWN 不参与猜测性硬排除。

## 4. aux-registry v2

格式：

```text
mainModId
mainFileId
mainVersion
kind
status
auxModId
auxFileId
auxVersion
auxName
checkedAt
evidence
note
```

核心变化：**结论绑定 mainFileId，而不是只绑定版本号。**

原因：Nexus 同一版本可能存在：

- 不同 Main File 变体；
- 同版本热修替换包；
- With CC / Without CC；
- AE / SE / VR；
- 2K / 4K / 8K。

仅用版本号会错误复用旧的 Patch/汉化结论。

## 5. NONE 也必须有证据

`NONE` 不是空白默认值。

必须有：

```text
checkedAt
evidence
```

默认 14 天后过期。

如果 scanner 已发现候选，但 registry 写 NONE：

```text
HOLD_CLOSURE_CONFLICT
```

Agent 必须解释为什么候选不适用，而不能静默绕过。

## 6. REQUIRED 必须 API 二次验真

`audit-registry.js` 对 REQUIRED 项检查：

- aux modId 是否可访问；
- aux fileId 是否存在；
- 是否已 OLD / ARCHIVED；
- fileId 当前版本与 registry 是否一致。

未通过 audit 的 REQUIRED 项不能进入下载清单。

## 7. 事务执行

每个主更新系列拥有 transaction id：

```text
mainModId:mainFileId
```

执行顺序：

```text
MAIN → PATCH → TRANSLATION → other aux
```

每一项都必须先 VERIFIED 才执行下一项。

如果其中一项失败：

```text
当前 tx = FAILED
后续项 = BLOCKED_BY_TX_FAILURE
```

不会继续污染 MO2 下载队列。

## 8. 可恢复执行

执行状态保存：

```text
.runtime/runs/<timestamp>/execution-state.json
```

状态包含：

- SUBMITTING
- SUBMITTED
- SUBMIT_FAILED
- VERIFIED
- VERIFY_FAILED
- VERIFY_TIMEOUT
- BLOCKED_BY_TX_FAILURE

同一状态文件中已经 VERIFIED 的 `modId:fileId` 不再重复提交。

## 9. AI 的职责

Pi/AI Agent 应做：

- 读取 review queue；
- 打开精确 Nexus 页面；
- 阅读 Files / Requirements / Translations / Description；
- 判断候选适配性；
- 为 registry 写入可审计证据。

Pi/AI Agent 不应做：

- 按最新上传猜 Main File；
- 删除 HOLD；
- 把 REVIEW 手工改成 DOWNLOAD；
- 无证据写 NONE；
- 用模糊文件名代替 fileId；
- 把 SUBMITTED 当成功。

## 10. 推荐命令

静态检查与回归测试：

```powershell
npm run check
npm test
```

只审计：

```powershell
node index.js "E:\\SkyrimAE\\mo2\\mods" "E:\\SkyrimAE\\tools\\.nexus_api_key" --force-refresh
```

真实执行：

```powershell
node index.js "E:\\SkyrimAE\\mo2\\mods" "E:\\SkyrimAE\\tools\\.nexus_api_key" --go --force-refresh
```

更严格的证据时效：

```powershell
node index.js ... --max-age-days 7
```

单个下载最长等待 30 分钟：

```powershell
node index.js ... --go --timeout-sec 1800
```

## 11. 安全策略

v3.1 明确接受更多 false negative：

> 不确定时 HOLD，宁可少自动更新，也不能错下 Main File、漏 Patch、漏汉化或错误宣告成功。

这是本项目后续优化必须保持的核心不变量。
