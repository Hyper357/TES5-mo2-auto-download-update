# v3.9 Phase 1 — Variant Decision Memory

目标：用户已经在 Review Center 明确选择过一个语义 Main 分支后，后续更新应沿该分支继续；不得每次重复询问，也不得在分支消失时自动回退到别的分支。

## 状态文件

用户偏好保存在本地运行状态：

```text
.runtime/state/variant-policies.json
```

该目录已被 `.gitignore` 忽略，因此 `git pull` 不会覆盖用户偏好，选择分支也不会污染 Git 工作区。

记录的是稳定的语义 `branchKey`，不是会随版本变化的 Nexus `fileId`。例如：

```text
HDT_SMP+KS_HAIRDOS
```

同时记录最后一次确认的 fileId/version/name 作为审计信息。

## 写入规则

Review Center 中只有用户**显式点击**某个 Main radio 后，提交 reviewed download 才会写入长期偏好。

页面默认勾选的当前分支不会因为用户只处理 Patch 就被偷偷记住。

`GENERIC` 分支不会持久化，因为它没有足够稳定的语义身份。

## 后续 Audit

若政策为：

```text
modId=160675
branchKey=HDT_SMP+KS_HAIRDOS
```

且新 Files 页仍有同一 branchKey，Planner 只在该分支内选择当前最新 Main；不会考虑 Vanilla/KS Full 等其他分支。

如果偏好分支消失、改名或标签结构变化：

```text
HOLD_VARIANT_POLICY_CHANGED
```

并进入 Review Center。系统不会自动退回其他分支。

## 查看与清除

```powershell
npm run variant:status
npm run variant:forget -- 160675
```

清除后，下次 Audit 会重新按普通多分支规则处理，由用户重新确认。

## 安全边界

Variant policy 只授权“产品分支偏好”，不绕过：

- Patch Discovery / Translation closure；
- Preflight；
- exact `modId:fileId`；
- queue idempotency；
- MO2 UI Guard；
- VERIFIED 完成条件。

分支策略变化时优先 HOLD，而不是猜测作者的新命名意图。
