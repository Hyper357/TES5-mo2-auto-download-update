# v3.5 — MO2 UI Queue Recognition + Safe Duplicate Dialog Guard

## Why this exists

v3.4 prevents most duplicate NXM submissions through three authoritative layers:

1. exact `modId:fileId` disk evidence in MO2 Downloads;
2. a cross-run submission ledger;
3. a single global executor lock.

MO2 can still display modal dialogs when a previous queue item exists but the filesystem/ledger has not yet converged, or when MO2 detects a same-name archive. A modal blocks later UI automation and creates the user-visible interruptions that motivated v3.5.

v3.5 adds a fourth, deliberately conservative layer: **MO2 UI observation**.

## Architecture

```text
Nexus exact fileId
      ↓
nxmhandler.exe
      ↓
MO2
      ├─ Downloads row / queue state ──────┐
      ├─ "already in queue" dialog         │
      └─ "re-download?" dialog              │
                                             ↓
                                   MO2 UI Guard
                                             ↓
                         only OK / No / Cancel are allowed
```

The UI layer never authorizes a download. It can only observe state or prevent a duplicate overwrite.

## Components

### `scripts/mo2-ui-state.ps1`

Uses Windows UIAutomation to enumerate the windows belonging to the active `ModOrganizer.exe` process. It returns:

- top-level MO2 windows;
- window text and button names;
- visible TreeItem/ListItem/DataItem text from the main window;
- native window handles used for a later exact safe-button invocation.

Invocation mode is fail-closed: if the requested button pattern matches zero or multiple buttons, nothing is clicked.

### `scripts/lib/mo2-ui-guard.js`

Pure deterministic policy layer. It:

- classifies duplicate-queue information dialogs;
- classifies re-download confirmation dialogs;
- scores target-name similarity;
- recognizes queue states (`DOWNLOADING`, `QUEUED`, `PAUSED`, `COMPLETE`, `INSTALLED`);
- emits safe actions only for `OK` or `NO` roles.

It has no implementation path for `YES`.

### `scripts/mo2-ui.js`

Node wrapper around the PowerShell snapshot/invoke layer. Examples:

```powershell
npm run mo2:status

node scripts/mo2-ui.js `
  --mod-id 97155 `
  --file-id 799389 `
  --name "ShowRaceMenu NG - Latest Version"
```

To apply only the deterministic safe actions:

```powershell
node scripts/mo2-ui.js `
  --mod-id 97155 `
  --file-id 799389 `
  --name "ShowRaceMenu NG - Latest Version" `
  --dismiss-safe
```

This command can only acknowledge a reliable duplicate-info dialog or cancel a reliable re-download prompt.

### `scripts/wake-mo2-download.ps1`

The existing NXM handoff path already calls this script. v3.5 attaches a short UI Guard watch before and during the wake loop, so normal pipeline execution does not need a separate background monitor.

## Dialog safety policy

### Already in download queue

Typical text:

```text
此文件已在下载队列中
模组 173086
文件 799456
ShowRaceMenu NG - Latest Version ...
```

The guard may invoke `确定/OK` when either:

- the dialog contains the expected `modId` and `fileId`; or
- the current pipeline target name strongly matches the dialog.

`OK` merely acknowledges the duplicate information; it never creates a second download.

### Re-download prompt

Typical text:

```text
重新下载？
已有同名的下载文件：ShowRaceMenu NG - Latest Version ...
```

The guard may only invoke:

```text
否 / No / Cancel
```

and only when the filename/name tokens strongly match the current target.

Qt accelerator labels such as `否(N)` and `No(&N)` are supported.

There is intentionally **no affirmative action** for:

```text
是(Y)
Yes
Retry
Re-download
Download
```

## Ambiguous dialogs

If a duplicate/re-download-like dialog exists but cannot be reliably tied to the current target, it is reported as ambiguous and left untouched.

Do not replace this with coordinate clicking, Enter/Y keystrokes, or broader regexes.

## Queue status

`queue:status` now combines:

```text
Disk evidence
+ submission ledger
+ executor lock
+ MO2 UI queue/dialog observation
```

Example:

```powershell
node scripts/queue-status.js `
  --mod-id 97155 `
  --file-id 799389 `
  --name "ShowRaceMenu NG - Latest Version"
```

Important fields:

```text
target.disk.status
target.ledger.status
target.resubmitGuard
mo2Ui.queue.state
mo2Ui.queue.inflight
mo2Ui.dialogs
mo2Ui.safety
```

UI queue evidence is supplemental. Exact `.meta/.unfinished`, ledger, and final `VERIFIED` remain authoritative.

## Failure posture

The system prefers a visible HOLD over a wrong UI click.

- UIAutomation unavailable → fall back to disk/ledger/verify.
- no unique safe button → do nothing.
- unrelated re-download dialog → do nothing.
- safe re-download cancellation → verify the existing exact file; do not immediately submit again.
- success still means `VERIFIED`, never merely “dialog closed”.
